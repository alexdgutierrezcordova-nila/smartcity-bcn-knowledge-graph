¿Cómo creamos los términos del vocabulario?\[22\] Para crear una clase propia:

1. Usamos rdf:type rdfs:Class para indicar que el nodo es una clase\[23\]\[24\].  
2. Usamos rdfs:label para darle un nombre (en inglés, español, etc.)\[24\].  
3. Usamos rdfs:comment para añadir una descripción del uso de la clase\[24\].  
4. La conectamos a clases existentes con rdfs:subClassOf o owl:equivalentClass\[24\].

Para crear una propiedad (rdf:Property):

1. Especificamos rdf:type rdf:Property\[25\].  
2. Definimos rdfs:label y rdfs:comment\[25\]\[26\].  
3. Fijamos el dominio (rdfs:domain) y el rango (rdfs:range)\[25\]\[26\]. Si es un atributo de datos, el rango será un tipo de dato XSD (como xsd:string o xsd:date)\[26\].

Veamos el ejercicio práctico de eventos académicos\[27\]. Se trata de modelar conferencias que ocurren anualmente\[27\]. Para modelar un evento académico:

* Usamos schema:Event o schema:ConferenceEvent como clase principal\[28\].  
* Para el nombre usamos schema:name\[29\].  
* Para las siglas o acrónimo podemos usar dbo:acronym\[30\].  
* Para las fechas de inicio y fin usaremos schema:startDate y schema:endDate\[31\]\[32\].  
* Para conectar el evento con la organización que lo realiza, la documentación de schema:event indica que la organización es el sujeto y el evento el objeto\[33\]\[34\].  
* La organización se conecta a una ciudad con schema:location (schema:Place)\[35\].  
* La ciudad se conecta al país con schema:containedInPlace\[35\]\[36\].

Para crear las tripletas en RDF/Turtle\[37\]:

1. Definimos la URI del evento general como tipo schema:ConferenceEvent con su schema:name y dbo:acronym\[37\]\[38\].  
2. Para cada edición anual (ej. 2025), creamos su URI y la vinculamos al evento general con schema:subEvent\[38\].  
3. Añadimos schema:startDate, schema:endDate y schema:url\[38\]\[39\].  
4. Relacionamos la organización con el evento mediante schema:event y la conectamos a su ubicación con schema:location\[39\].  
5. Para las fechas importantes específicas (como límite de recepción o notificación), si no existen propiedades en el estándar, creamos un recurso de tipo schema:Schedule con propiedades propias (vocab:dislike, vocab:notification, etc.)\[37\]\[41\].
